## 요약

- 원본 ID는 다르지만 사실상 같은 사진이 서로 다른 split에 들어간 경우가 **1쌍** 있었음. **46217(train)과 54313(val)**이며 같은 자동차 충돌 시험 사진임.
- AutoSplice test나 CocoGlide와 겹치는 근접 중복은 이번 방법으로는 발견되지 않음.
- 이 방법은 리사이즈·재압축된 중복을 찾는 방법임. 크롭·좌우반전·큰 편집을 거친 중복은 찾지 못하므로 누수가 전혀 없다고 결론내리지 않음.
- 46217–54313을 어떻게 처리할지(분할 유지 또는 새 분할 파일)는 팀 결정이 필요함. 분할 CSV는 수정하지 않음.

## 배경과 목적

002는 파일 바이트(SHA-256)와 디코드 RGB가 **완전히 같은** 이미지만 검사했고 0개였음. SHA-256은 픽셀 하나만 달라도 다른 값이 되므로, 같은 사진이 다른 크기나 압축으로 다시 저장된 경우는 찾지 못함. 002 보고서와 TODO는 이를 T05의 남은 일("근접 중복 검토 범위를 정한 뒤 고정 분할을 최종 확인")로 남겼음.

같은 사진이 train과 val·test에 나뉘어 있으면 모델이 학습한 사진으로 검증·평가를 받는 셈이 되어 점수가 실제보다 높게 나올 수 있음. 이번 작업은 이런 근접 중복을 찾아 고정 분할을 그대로 쓸 수 있는지 판단할 근거를 만듦.

## 검사 방법

근접 중복을 찾는 방법은 팀 규약으로 정해진 것이 없었음. 아래 방법과 기준값은 이번 작업에서 seonghun이 정한 것이며, 팀이 확정한 규약이 아님.

### 1. 대상

| 그룹 | 이미지 수 | 비고 |
| --- | ---: | --- |
| AutoSplice train | 1,818 | 정상 원본 |
| AutoSplice val | 227 | 정상 원본 |
| AutoSplice test | 228 | 정상 원본 |
| CocoGlide | 512 | 정상(real) 이미지, 외부 테스트 |

AutoSplice 조작본(JPEG 100·90·75)은 같은 원본 ID로 원본과 같은 split에 묶여 있으므로 정상 원본만 비교하면 됨. CocoGlide 조작본도 같은 이유로 제외함. test와 CocoGlide는 중복 검사에만 사용함.

### 2. perceptual hash

이미지마다 "생김새 요약값"인 64비트 perceptual hash를 계산함. SHA-256과 달리 **비슷하게 생긴 이미지는 비슷한 값**이 나오고, 크기 변경·재압축에는 값이 거의 변하지 않음.

| 해시 | 계산 방법 |
| --- | --- |
| pHash | 회색조 → 32×32로 축소 → 2차원 DCT → 저주파 8×8 계수가 중앙값(DC 제외)보다 큰지 여부 |
| dHash | 회색조 → 9×8로 축소 → 가로로 이웃한 두 픽셀 중 오른쪽이 더 밝은지 여부 |

이미지는 공통 함수 `scripts.preprocessing.load_rgb`로 읽고, 축소는 Pillow LANCZOS를 사용함. 새 패키지는 사용하지 않음.

### 3. 비교와 후보 선별

- 두 해시의 **해밍 거리**(64비트 중 서로 다른 비트 수)를 모든 쌍에 대해 계산함. 0이면 거의 같은 이미지, 서로 무관한 사진은 보통 30 안팎임.
- **서로 다른 그룹 사이의 쌍만** 누수 후보로 봄. 같은 그룹 안의 쌍은 참고 개수만 기록함.
- pHash 또는 dHash 거리가 **10 이하**이면 후보로 표시함. 10은 검토할 쌍을 고르기 위한 값이며 학습 설정과 무관함.
- 기준값만 믿지 않도록, 기준과 관계없이 그룹 간 pHash 거리가 가장 가까운 **상위 20쌍**도 함께 검토 목록에 넣음.

### 4. 사람의 확인

검토 목록을 두 거리 중 작은 값 순으로 정렬해, 쌍마다 두 이미지를 좌우로 나란히 그림(상위 40쌍). 같은 장면을 같은 순간에 찍은 사진이면 중복, 구도·색감만 비슷하거나 같은 인물·장소라도 다른 사진이면 중복이 아닌 것으로 판단함.

### 작성 단계 점검

Colab 실행 전 로컬 합성 데이터로 코드 동작을 확인함. 다른 split에 리사이즈·재압축해 심은 중복 3쌍과 AutoSplice–CocoGlide 교차 중복 1쌍이 모두 거리 0으로 목록 맨 위에 나옴. 합성 데이터 결과는 실제 결과에 포함하지 않음.

### 사람이 확인한 쌍 (6절)

검토 목록은 53쌍(기준 이하 후보 34쌍 + 기준 밖 최근접 19쌍)이며, 그중 상위 40쌍을 그림으로 확인함.

| 구분 | 쌍 수 | 거리 | 판단 |
| --- | ---: | --- | --- |
| 46217(train) – 54313(val) | 1 | pHash 0, dHash 0 | **같은 사진.** 차량 위치·차체 문구(`2002 HONDA CRV`, `CEF0213`)·구도가 같고 두 파일 모두 256×360 |
| 나머지 기준 이하 후보 | 33 | dHash 7~10, pHash 20~36 | 다른 사진 |
| 그림으로 본 기준 밖 쌍 | 6 | pHash 12, dHash 15~23 | 다른 사진 |
| 그림 표시 범위 밖 | 13 | pHash 12~14, dHash 22 이상 | 그림으로 확인하지 않음. 표의 거리상 같은 사진일 가능성은 낮음 |

dHash만 가까웠던 쌍은 구도가 비슷한 다른 사진이었음. 예를 들어 어두운 배경의 인물 상반신(54467·54769, 40468·43331), 증명사진 형태의 얼굴(51199·56407, 39886·52169), 흰 배경의 물체(60912·65777)가 있음. dHash 단독 후보는 오탐이 많으므로 두 거리를 함께 봐야 함.

검토 목록은 이미지 두 장의 쌍 단위이므로 같은 이미지가 여러 줄에 나올 수 있음. 45749(눈 속 늑대)는 5쌍, 54411(안경에 비친 화면)은 4쌍, 72067·65777은 각 2쌍에 나왔으며 짝은 모두 다른 사진이었음. 가운데 물체와 단순한 배경, 넓은 어두운 영역, 증명사진 구도처럼 축소한 밝기 패턴이 평범한 이미지는 여러 사진과 두루 가깝게 계산됨. 이 쌍들은 모두 dHash만 작고 pHash는 22 이상이었음. 반면 46217–54313은 서로에게만 거리 0이었고 다른 쌍에는 나오지 않음. 여러 쌍에 반복해서 나오는 이미지는 중복보다 해시의 구분력이 낮은 경우로 해석함.

40468(train)과 52191(val)에는 같은 인물이 나오지만 옷·배경·각도가 다른 별개의 사진이어서 이미지 중복으로 보지 않음.

판단 기록: 46217–54313이 같은 사진임은 seonghun이 그림에서 확인함. 나머지 39쌍의 판단은 2026-11-23 에이전트가 저장된 그림을 보고 기록한 것이며, 노트북 7절의 사람 검토 메모는 아직 채워지지 않았음.

## 분석

### 중복이 생긴 이유 (추정)

AutoSplice 원본은 뉴스 기사 이미지로 보임. 뉴스에서는 같은 자료 사진이 여러 기사에 반복해서 쓰이고, 기사마다 다른 ID가 붙음. 각 기사에서 이미지를 따로 내려받거나 다시 저장하면 픽셀이 조금씩 달라지므로, 002의 완전 일치 검사로는 찾을 수 없고 perceptual hash로는 거리 0이 됨. 원본 출처와 실제 원인은 데이터셋 문서와 두 ID의 `Caption/` 내용을 비교해 확인해야 하며, 이번 실행에서는 확인하지 않음.

원본 ID 기준 분할은 같은 원본의 파생 이미지 누수는 막지만, 다른 ID로 들어온 같은 사진은 막지 못함.

### 영향

- test·CocoGlide와 겹친 사진은 발견되지 않았으므로 최종 평가 점수에 대한 영향은 이번 검사 범위에서 확인되지 않음.
- 54313은 val이므로 조기 종료·체크포인트 선택에 쓰이는 val 성능이 이 이미지(정상 원본과 그 조작본)만큼 약간 낙관적으로 나올 수 있음. val 정상 원본 227장 중 1장임.
- train 안에서도 pHash 0인 쌍이 있음. 같은 split이라 누수는 아니며, 같은 사진이 학습에 두 번 쓰이는 정도임. 이 쌍들은 그림으로 확인하지 않음.

## 결론과 남은 사항

리사이즈·재압축 형태의 근접 중복은 그룹 간 1쌍(46217 train – 54313 val)이며, 나머지 후보는 다른 사진이었음. 거리 분포의 간격으로 볼 때 이 형태의 중복은 이 한 쌍이 전부로 판단함.

팀이 정해야 할 것:

1. **46217–54313 처리**
   - 분할 유지 + 한계 기록: 분할 CSV와 모든 노트북의 해시가 그대로 유지됨. CAT-Net 학습(kimjaehak 005·006)과 U-Net 실험(T09)이 현재 분할을 사용 중임.
   - 54313을 train으로 옮긴 새 분할 파일: 기존 CSV는 덮어쓰지 않고 새 파일명·새 해시로 만들며, 이후 모든 실험이 새 파일을 사용해야 함.
2. **추가 검사 여부**: 크롭·좌우반전·큰 편집·연속 촬영 사진은 이 방법으로 찾지 못함. 필요하면 좌우반전 해시 추가나 사전학습 CNN 특징의 유사도 비교를 새 번호로 진행함.
3. **같은 인물·장소의 다른 사진**을 누수로 볼지. 이번 검사는 이미지 중복만 대상으로 함.

### 한계

- perceptual hash는 크롭·회전·좌우반전·큰 편집에 약함. 후보가 없다는 것이 누수가 없다는 뜻은 아님.
- 사람 확인은 거리 상위 40쌍만 그림으로 함.
- 같은 그룹 안의 후보는 개수만 기록하고 그림으로 확인하지 않음.
- 근접 중복 검사 방법과 기준값 10은 팀이 확정한 규약이 아님.
