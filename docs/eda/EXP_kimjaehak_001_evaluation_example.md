## 목적

고정된 원본 ID 분할을 읽고 AutoSplice와 CocoGlide의 이미지·마스크를 연결하는 예제임. 실제 정답 마스크를 바꾼 설명용 예측으로 `confusion_counts`, `pixel_f1`, `iou`, `false_positive_rate` 사용법을 확인함.

확인할 동작은 정답과 같은 예측에서 F1·IoU가 1, 조작을 전부 놓친 예측에서 0, 정상 이미지의 무오탐에서 오탐률이 0이 되는지임. 각 식의 분모가 0이면 `None`을 반환하는지도 확인함. 모델 우열이나 ELA 효과에 대한 가설은 다루지 않음.

## 데이터와 분할

입력은 사용자가 제공한 AutoSplice.zip과 CocoGlide.zip임. Colab에서 공유 Drive의 `AI_Forensics/datasets`를 읽고 ZIP을 `/content`로 복사해 `/content/datasets`에 해제한 출력을 확인함. 저장소에는 데이터 파일을 추가하지 않음.

AutoSplice는 [공통 CSV](../../scripts/splits/autosplice_seed42.csv)를 사용함. 원본 2,273개를 숫자순 정렬하고 `random.Random(42).shuffle`로 섞은 뒤 학습·검증 개수는 각각 80%·10%의 정수 내림, 나머지는 테스트로 배정함. 같은 원본의 정상·조작본과 세 JPEG 품질 변형은 같은 split에 배정함. 조작본이 없는 정상 원본도 포함함. 성능을 보고 시드를 고르지 않음.

| AutoSplice split | 원본 ID / 정상 이미지 | 조작 이미지 수, JPEG 품질별 |
| --- | ---: | ---: |
| train | 1,818 | 2,925 |
| val | 227 | 361 |
| test | 228 | 335 |
| 합계 | 2,273 | 3,621 |

노트북 3절의 Colab 저장 출력에서 위 개수와 JPEG 100·90·75의 분할 일치 확인 문구를 재확인함. 정상 이미지는 Authentic 제공 파일 그대로 사용하며 JPEG 100 이미지로 재압축하지 않음. 원본 ID 외의 내용 중복 여부까지 점검한 것은 아님. [분할 생성 기록](../../scripts/splits/README.md)에 재현 명령과 해시를 기록함.

CocoGlide는 `table.csv`의 512개 real·fake·mask 연결을 읽음. 정상 512장과 조작 512장을 `external_test`로 표시하고, 학습·검증 분할을 만들지 않음. PNG를 그대로 읽으며 제안서의 JPEG 100·90·75 변환 평가는 수행하지 않음.

## 예시 선택과 설정

| 데이터셋 | 선택 기준 | 원본 ID | 조작 이미지 | 마스크 | 크기, 높이×너비 |
| --- | --- | --- | --- | --- | --- |
| AutoSplice | train 조작 파일 이름순 첫 항목 | 39406 | Forged_JPEG100/39406_0.jpg | Mask/39406_mask.png | 256×374 |
| CocoGlide | table.csv 첫 행 | 114871 | fake/glide_inpainting_val2017_114871_up.png | mask/dining table_114871_mask.png | 256×256 |

대응 정상 이미지는 각각 `Authentic/39406.jpg`, `real/dining table_114871.png`임. 선택 기준은 점수 계산 전에 정했으며 결과에 따라 바꾸지 않음. 정상·조작 각 1장씩, 두 데이터셋 합계 4장을 예제에 사용함.

- 전경값: 255를 조작 픽셀 1로 변환함. 선택 이미지의 원본·조작본·마스크를 시각화해 위치와 크기를 확인함.
- 설명용 확률: 예측 1은 0.9, 예측 0은 0.1로 구성함. 임계값 0.5 이상을 조작으로 판정함. 모델 출력이 아님.
- 혼합 오류: 조작 픽셀을 행 순서로 나열해 매 5번째를 누락시키고, 정상 픽셀의 매 100번째에 오탐을 추가함.
- 정상 오탐: 좌측 상단의 `높이//10 × 너비//10` 사각형을 조작으로 예측함.
- 원본 크기로 계산함. 리사이즈·크롭·ELA·JPEG 증강·후처리를 적용하지 않음.
- 데이터셋 전체 성능 평균은 계산하지 않음. 정상 이미지는 F1·IoU 기록에서 제외하고 오탐률만 계산함.
- 모델·손실·최적화·학습 예산·체크포인트·모델 추론 시간은 해당 없음임.

### 정성 확인과 해석

4절 그림에서 AutoSplice의 선박 일부가 버스로 바뀐 영역과 마스크 위치가 대응함을 확인함. CocoGlide는 바나나·접시가 있는 원본과 식탁 장면의 조작본이 표시되며, 마스크가 대부분의 화면을 차지함. 크기는 AutoSplice 256×374, CocoGlide 256×256이고 해당 출력과 그림이 일치함. 전체 데이터의 모든 마스크 정합성을 확인한 것은 아님.

5절의 설명용 예측에는 규칙적으로 지운 조작 픽셀과 추가한 오탐 픽셀이 보임. 두 예시의 조작 영역 크기가 달라 같은 오류 생성 규칙에서도 F1·IoU가 다르게 나옴. 이는 모델의 성공·실패나 데이터셋 난이도 차이로 해석하지 않음. 6절에서는 정상 정답이 모두 검정이고 좌측 상단에만 설명용 오탐 영역이 표시됨.

### 당시 정성 확인과 해석

노트북 4절에는 정상·조작 이미지와 정답 마스크, 5절에는 조작 이미지·정답·설명용 예측, 6절에는 정상 이미지·0 마스크·오탐 예측을 각각 두 데이터셋에 대해 표시함. 세 그림의 출력과 제목을 확인함.

AutoSplice 예시는 선박이 있는 부분에 버스가 생성된 조작본이며 마스크도 해당 위치를 표시함. CocoGlide 예시는 정답 조작 픽셀이 63,780/65,536으로 화면 대부분을 차지함. 같은 누락·오탐 생성 규칙을 적용해도 양성·음성 픽셀 수가 달라 F1·IoU는 달라짐. 이번 숫자의 차이는 모델 성능 차이가 아님.

정답과 일치하는 경우와 전부 놓치는 경우는 함수의 동작 확인용 성공·실패 사례임. 실제 탐지 모델의 성공·실패 사례 분석은 아직 수행하지 않음.
