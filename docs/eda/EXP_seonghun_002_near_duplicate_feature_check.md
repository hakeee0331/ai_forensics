## 요약

- 서로 다른 split 사이의 중복은 001에서 찾은 **46217(train)–54313(val) 1쌍**뿐임. 이 방법에서도 특징 유사도 0.9921, pHash 0으로 다시 확인됨.
- 같은 split 안에서는 **train 내부 중복 9쌍**을 찾음. 8쌍은 같은 사진(유사도 0.990 이상, pHash 0~2), 1쌍은 같은 사진을 다르게 자른 크롭 중복임.
- **57665(val)–69776(train)**은 같은 해파리 장면의 다른 프레임으로 보임. 같은 순간의 사진이 아니므로 중복으로 보지 않음(seonghun 판단, 2026-11-23).
- train 내부 중복은 현재 분할에서 누수가 아니며 그대로 둠(seonghun 결정, 2026-11-23). 분할을 다시 만들 때는 같은 묶음으로 처리해야 함.
- 분할 CSV는 수정하지 않음. 분할 생성은 다른 담당자가 진행함.

## 목적

001은 perceptual hash로 리사이즈·재압축된 중복을 찾았으나, 같은 방법으로는 크롭·좌우반전·큰 편집·연속 촬영 사진을 찾지 못함. 팀이 분할 변경에 동의했으므로(2026-11-23), 새 분할을 한 번에 만들 수 있도록 남은 중복을 찾아 목록으로 정리함.

분할을 다시 만들 때는 같은 split 안의 중복도 같은 묶음으로 다뤄야 서로 다른 split으로 갈라지지 않음. 그래서 이번에는 그룹 간뿐 아니라 모든 쌍을 비교함.

## 방법

| 항목 | 설정 |
| --- | --- |
| 대상 | 001과 같음. AutoSplice 정상 원본 2,273장(train 1,818 / val 227 / test 228), CocoGlide 정상 512장 |
| CNN 특징 | torchvision ResNet-50 `IMAGENET1K_V2`, 전역 평균 풀링 출력 2,048차원. 자르지 않고 224×224로 축소, ImageNet 평균·표준편차 정규화, 길이 1로 정규화 |
| 특징 유사도 | 코사인 유사도와 한쪽을 좌우반전했을 때의 코사인 유사도 중 큰 값. 1에 가까울수록 비슷함 |
| pHash | 001과 같은 계산. 원본끼리와 한쪽을 좌우반전했을 때의 해밍 거리 중 작은 값 |
| 비교 범위 | 모든 쌍(그룹 간 + 같은 그룹 안) |
| 후보 기준 | 특징 유사도 ≥ 0.90 또는 pHash ≤ 10. 검토 후보 선별용이며 학습 설정이 아님 |
| 사람 검토 | 기준 후보 전부 + 특징 유사도 상위 60쌍. 그림은 유사도 순 상위 60쌍(#0~#59) |
| 확인용 기준 쌍 | 001에서 찾은 46217–54313 |

CNN 특징은 사진의 내용을 비교하므로 크롭·편집·색 보정에도 비교적 강하지만, 같은 인물이나 같은 종류의 동물을 찍은 다른 사진도 높게 나옴. 그래서 사람이 그림으로 판단함. 001에서 오탐이 많았던 dHash는 쓰지 않음. 방법과 기준값은 이번 작업에서 seonghun이 정한 것이며 팀 규약이 아님.

판단 기준: 같은 순간에 찍은 같은 사진이면 크기·크롭·압축이 달라도 중복으로 봄. 같은 인물·장소·물체라도 다른 순간에 찍은 사진이면 중복이 아님.

그림에 나오지 않은 11쌍(#60~#70)은 유사도 0.895 미만이고 pHash ≤ 10이라 후보가 된 쌍임. 저장된 표에서는 그중 5쌍(유사도 0.08~0.12)만 보이며 내용이 무관한 사진의 pHash 우연 일치로 판단함. 나머지 6쌍은 표 출력이 생략돼 확인하지 못함. 그룹 간 후보 11쌍은 모두 확인함(그림 9쌍, 표 2쌍).

### 중복이 생긴 이유 (추정)

`Authentic/`에는 원본 ID마다 파일이 한 장이고, 압축률만 다른 파일은 조작본 폴더(`Forged_JPEG100/90/75`)에만 있으며 이번 대상이 아님. 정상 원본은 짧은 변 256으로 저장돼 있고, byhyun 001의 표본에서는 모두 Q75·4:2:0이었음. 002 EDA에서 픽셀까지 같은 이미지는 0개였음.

따라서 이 중복은 최종 파일의 압축률 차이가 아니라, **같은 원본 사진이 서로 다른 ID로 두 번 수집된 것**으로 보임. 뉴스 기사 이미지에서 같은 자료 사진이 여러 기사에 쓰이고, 기사마다 받은 사본을 각각 축소·재저장하면 눈으로는 같지만 픽셀은 조금 다른 파일이 됨. 원본 출처와 두 파일의 양자화 테이블·픽셀 차이는 확인하지 않음.
