## 목적

`scripts/preprocessing.py`에 수정·추가된 함수가 Colab에서 [사용 안내](../preprocessing.md)대로 동작하는지 확인하고, 평가용 패딩이 실제 AutoSplice 이미지에서 원본 위치와 크기를 지키는지 확인함. 확인 대상은 아래 세 가지임.

- `load_binary_mask`: `foreground_value`에 NumPy 정수를 허용하고 불리언은 거부함.
- `make_ela`: `scale`이 불리언·문자열·복소수·무한대·비양수이면 `ValueError`를 발생시킴.
- `pad_image`, `unpad_image`: 높이·너비를 32의 배수로 올려 우하단에 0을 채우고, 원본 크기로 되돌림.

EXP_byhyun_001에서 입력 검증 문제와 패딩 규칙이 남아 있다고 기록했고, 이 노트북은 그 이후 반영된 코드를 확인함. 사용 안내(2026-11-20)는 ELA 설정(quality 90, scale 15, subsampling 2)과 평가용 우하단 제로 패딩(32의 배수)을 팀 합의로 기록함. 이 노트북은 그 설정으로 ELA를 만들어 패딩을 확인했으며, 설정 자체의 타당성은 범위가 아님. 모델 학습이 필요한 항목과 평가 임계값·집계·학습 조건도 범위가 아님.

입력은 공유 Drive의 AutoSplice.zip과 [공통 분할 CSV](../../scripts/splits/autosplice_seed42.csv)임. ZIP은 코드에 고정한 기대 해시와 대조해 확인함. 실제 데이터 확인에는 AutoSplice val 분할의 조작 이미지(JPEG 품질 100 파일)와 마스크 쌍 361장 전체를 사용함. train·test와 CocoGlide는 사용하지 않음.

| 절 | 대상 | 표본 |
| --- | --- | --- |
| 2절 합성 입력 | 임의 RGB `(45, 53, 3)`(seed 42), 마스크 `(40, 50)`, 배열 `(64, 96)` | 각 1개 |
| 3절 실제 데이터 | val 조작 이미지와 마스크 | 전체 361장 |

## 확인 방법과 설정

| 항목 | 내용 |
| --- | --- |
| ELA 설정 | quality 90, scale 15, subsampling 2를 인자로 직접 전달함 |
| 패딩 | `multiple=32`, 좌측 상단 (0, 0) 고정, 우하단 제로 패딩 |
| 전경값 | 실제 마스크는 255. 합성 마스크는 `np.int64(255)`와 `True`로 확인함 |
| 압축 해제 위치 | `/content/datasets`. ZIP 안의 `AutoSplice` 폴더를 `/content/datasets/AutoSplice`로 읽음 |
| 평가 순서 | 원본 해상도에서 RGB·마스크를 읽고 ELA를 먼저 계산한 뒤 패딩함 |
| 제외 | 모델 학습·추론, 모델 출력의 언패딩, train·test, CocoGlide, 크롭·좌우반전 흐름, `evaluation.py`, JPEG 증강 |

3절은 이미지마다 아래 여섯 가지를 `assert`로 확인함.

1. 이미지·마스크·ELA의 원본 크기가 같음.
2. 패딩된 ELA의 높이·너비가 32의 배수임.
3. 패딩된 ELA와 패딩된 마스크의 크기가 같음.
4. 패딩된 ELA의 좌측 상단이 원본 ELA와 같음.
5. 패딩 영역의 ELA 합이 0임.
6. 패딩된 마스크를 `unpad_image`로 되돌리면 원본 마스크와 같음.

## 해석 — 2026-11-20

아래는 위 저장 출력에 대한 해석이며 모델 성능이나 팀 합의가 아님.

**수정 사항의 동작.** 합성 입력에서 NumPy 정수 전경값은 허용되고 불리언은 거부되었으며, 잘못된 scale 6가지는 모두 `ValueError`로 처리됨. EXP_byhyun_001 시점의 [사용 안내](../preprocessing.md)가 남은 문제로 기록한 세 가지(`scale=True`, 문자열·복소수 scale의 오류 종류, `np.int64` 전경값)는 이 실행에서 모두 의도대로 동작함.

**패딩과 복원.** val 조작 이미지 361장 모두에서 패딩된 크기가 32의 배수이고, 패딩된 ELA의 좌측 상단이 원본과 같으며, 패딩 영역이 0이고, 마스크가 위치 이동 없이 복원됨. 그림도 이와 같음. 패딩이 필요했던 비율 69.3%는 EXP_byhyun_001에서 센 val의 32의 배수가 아닌 크기 비율 69.3%와 같음.

**한계.** 확인은 AutoSplice val 조작 이미지에 한정함. train, test, 정상 이미지, CocoGlide의 크기와 패딩은 확인하지 않음. 모델 출력을 언패딩하는 흐름은 모델이 없어 마스크로 대신 확인함. 패딩 영역은 평가에서 `unpad_image`로 제거한 뒤 원본 마스크와 비교해야 하며, 이 노트북은 그 비교의 지표 계산을 하지 않음. ELA를 패딩 전에 계산하는 순서만 확인했고 패딩 후에 계산하는 순서와의 차이는 비교하지 않음. 입력 검증 확인은 나열한 값에 한정하며 모든 입력에 오류가 없다는 뜻이 아님.
