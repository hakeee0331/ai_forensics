## 목적·가설

006에서 AutoSplice 조작본의 마스크 밖에만 Q75 압축 흔적이 남고, CocoGlide에는 격자 흔적이 없으며 부분 편집임을 확인함. 004·005는 CocoGlide JPEG100을 통째로 칠했음. 학습 중 압축 격자를 깨고(지름길 끄기) 흔적 없는 정상 이미지를 함께 학습하면 CocoGlide 과탐지가 줄고 위치 정보가 생긴다는 가설을 세움.

이 실험은 **제안서에 없는 추가 실험**이며 CocoGlide 테스트 결과를 보고 설계함. 성공 기준은 실행 전에 고정함: CocoGlide JPEG100에서 정상 오탐률이 005(0.957)보다 확실히 낮고 픽셀 AUC·쌍 차이 AUC가 0.5를 확실히 넘음.

## 구현 문제: 격자 깨기가 거의 적용되지 않음

축소 비율을 "짧은 변 256 이상"으로 제한했고, 이동은 짧은 변이 263 미만이면 축소로 넘기게 했음. [kimjaehak 002](../eda/EXP_kimjaehak_002_dataset_eda.md)에 따르면 학습 이미지의 짧은 변 90백분위수가 256이라, 대부분의 이미지에서 축소 비율이 1.0이 되어 **아무 변화가 없었음**. 4절 증강 확인 표(39406_0.jpg, 374×256)에서 확인됨.

| 설정 | 크기 | Q75 정렬도 안 / 밖 |
| --- | --- | --- |
| 증강 없음(JPEG100 파일) | 374×256 | 0.249 / 0.159 |
| q=85 재저장(005 방식) | 374×256 | 0.262 / 0.215 |
| `resize x1.00` → q=85 | 374×256 | 0.262 / 0.215(재저장만 한 것과 같음) |
| 3·5픽셀 이동 → q=85 | 369×253 | 0.260 / 0.267 |

학습 로그의 `break` 0.50은 깨기 단계가 호출된 비율이며 실제 적용 비율이 아님. 따라서 007은 사실상 **"005 + 정상 이미지 포함 + 깨기가 호출된 절반의 4:4:4 재저장 섞임"**임. 합성 데이터의 이미지가 256보다 커서 작성 단계 검사에서 드러나지 않았음. 008에서 수정함.

## 분석

아래는 저장 출력에 대한 해석이며 팀 합의가 아님. 시드 1회 실행이고, 격자 깨기가 거의 적용되지 않았으므로 **격자 깨기의 효과로 해석하지 않음.**

**정상 이미지 포함은 005의 부작용을 해결함.** AutoSplice 정상 오탐률이 0.323에서 0.051로 줄고, 조작 F1도 세 품질 모두 올랐음(+0.019·+0.024·+0.011).

**CocoGlide JPEG100 과탐지는 거의 그대로임.** 정상 오탐률 0.957 → 0.922, 쌍 차이 AUC 0.514로 미리 정한 성공 기준을 넘지 못함. 정상 이미지를 학습해도 CocoGlide를 통째로 칠하는 경향이 남은 것은, 원인이 정상 이미지 부족보다 006의 압축 흔적 지름길 쪽에 있음을 시사함. 픽셀 AUC(0.636)가 쌍 차이 AUC(0.514)보다 크게 높아, CocoGlide에서 보이는 위치 정보의 상당 부분은 장면 내용(물체 영역)에서 옴.

**CocoGlide JPEG90·75에서는 칠하는 양이 늘었음.** 정상 오탐률이 005보다 높아졌고(0.51·0.49 → 0.64·0.60), 쌍 차이 AUC는 조금 올랐음(0.55·0.59 → 0.59·0.61).
