## 목적·가설

같은 이미지의 RGB와 ELA를 합친 6채널 입력 ResNet-50 U-Net을 002·003과 같은 조건으로 학습해, 두 정보를 결합한 효과를 확인함. 002·003은 AutoSplice JPEG100에서 높았지만 JPEG90·75와 CocoGlide에서 함께 무너져 압축 이력에 의존한 것으로 보였음. 결합 입력이 이 경향을 줄이는지 확인함.

002·003에서 바꾼 조건은 입력(6채널)과 conv1 초기화뿐임.

## 데이터

002·003과 같음. 학습은 AutoSplice train 조작 2,925장(JPEG 100, 정상 제외), 검증은 val 조작 361장·정상 227장, 테스트는 AutoSplice test JPEG 100·90·75 조작 각 335장과 정상 228장, CocoGlide 정상·조작 각 512장(PNG→JPEG100·4:4:4)으로 합계 2,257장임. 3절의 첫 배치 마스크 비율 16개가 002·003과 같아 같은 시드에서 같은 표본·크롭 위치가 뽑혔음을 확인함.

## 모델·학습

| 항목 | 값 |
| --- | --- |
| 모델 | ResNet-50(IMAGENET1K_V2) 인코더 U-Net, 002·003과 같은 구조. 파라미터 32,530,385개(3채널 모델보다 9,408개 많음) |
| 입력 | RGB 3채널 다음 ELA 3채널의 6채널. 각각 0~1 변환 후 ImageNet 평균·표준편차 정규화(T06 미확정) |
| conv1 | `(64, 6, 7, 7)`. RGB 쪽과 ELA 쪽 모두 RGB 사전학습 가중치를 복사(제안서). 크기 조정 없음. 4절 출력에서 두 쪽 모두 사전학습 가중치와 일치함을 확인 |
| ELA | quality 90, scale 15, subsampling 2. 팀 확정 규약 |
| 처리 순서 | 원본 전체에서 ELA 계산 → RGB·ELA·마스크를 같은 위치 256×256 크롭(좌표 16의 배수) → 확률 0.5 같은 좌우반전. 팀 확정 규약 |
| 손실 | BCEWithLogits + 이미지별 soft Dice 평균(ε=1), 1:1. 002에서 val로 선택 |
| 최적화·학습량 | Adam 1e-4 고정, 배치 16(epoch당 182 step), 시드 42, 최대 30 epoch, val 조작 평균 F1 기준 patience 5 |
| JPEG 증강 | 미사용. 002·003과 조건을 맞추기 위함 |

## 분석 — 2026-11-24

아래는 저장 출력에 대한 해석이며 팀 합의가 아님. 세 실험 모두 시드 1회 실행이라 작은 차이의 신뢰 구간은 알 수 없음.

**같은 압축 조건에서는 RGB+ELA가 가장 높지만 차이는 작음.** val F1과 JPEG100 F1 모두 셋 중 가장 높으나 RGB와의 차이는 각각 0.004, 0.003임. ELA 단독과 비교하면 RGB를 함께 넣어 val F1이 0.952에서 0.968로, 정상 오탐률이 0.0125에서 0.0009로 개선되고 학습 곡선도 안정됨. 반면 30 epoch 상한까지 학습했고 epoch 30에서 patience도 함께 충족되어, 상한을 늘렸을 때 더 오를지는 알 수 없음.

**재압축에는 ELA의 약점을 물려받음.** JPEG90에서 F1 0.005로 RGB(0.279)보다 크게 낮고 ELA 단독(0.001)과 비슷함. 003에서 추정한 대로, ELA(quality 90)는 이미 Q90으로 저장된 입력에서 0에 가까워져 신호가 사라질 수 있음. 결합 모델이 RGB 채널을 함께 받는데도 JPEG90에서 함께 무너진 것은, 학습 중 ELA 채널의 신호에 크게 기댔기 때문으로 보임. 채널별 기여는 측정하지 않았음.

**CocoGlide는 세 모델 모두 같은 방식으로 실패함.** 조작 F1이 0.359~0.361로 거의 같고 정상 오탐률이 0.94~0.98임. 7절 그림에서도 CocoGlide 조작·정상 이미지를 거의 통째로 칠했음. 입력이 달라도 같은 값에 수렴한 것은, 위치를 맞히지 못하고 이미지 대부분을 조작으로 예측해 생긴 값이기 때문으로 보임. 이미지 전체를 조작으로 예측할 때의 기준 F1은 계산하지 않았으며 후속 분석에서 확인함.

**압축 이력 해석.** 002·003에서 세운 해석(마스크 밖은 Q75→Q100 두 번 압축, 마스크 안은 Q100 한 번 압축이라 모델이 이 차이로 경계를 긋는다)과 결과가 그대로 맞음. CocoGlide는 원래 COCO JPEG 사진에서 만들어졌을 것으로 보이나 256×256으로 줄이며 예전 블록 흔적이 흐트러졌을 가능성이 크고, 우리가 Q100으로 한 번 저장하면서 AutoSplice의 마스크 안과 비슷한 상태가 된 것으로 추정함. 이 해석은 압축 흔적을 직접 측정해 확인해야 함.

**비용.** 6채널 입력과 ELA 계산으로 epoch당 시간이 RGB의 약 1.4배(학습 37초·검증 21초 대 30초·12초)임.

## 결론과 후속 작업

- 세 U-Net 기본 비교(002·003·004)를 같은 조건으로 마침. 같은 압축 조건(AutoSplice JPEG100)에서는 RGB+ELA ≥ RGB > ELA 순이지만 차이는 작음. 재압축에서는 RGB만 JPEG90에서 일부 남았고, ELA가 들어간 두 모델은 거의 0임. CocoGlide에서는 세 모델 모두 이미지 대부분을 조작으로 예측함.
- 현재 조건(JPEG100 학습, 증강 없음)에서는 입력 구성을 바꿔도 일반화 문제가 해결되지 않음. JPEG 증강(T14)을 앞당겨 세 입력을 다시 비교할 필요가 있음.
- 압축 흔적 분석: 마스크 안·밖의 블록 흔적, JPEG90 입력의 ELA 크기, CocoGlide 원본의 블록 흔적, CocoGlide 전체 조작 예측 기준 F1을 측정해 위 해석을 확인함.
- CAT-Net과 공정하게 비교하려면 같은 데이터·분할·선택 기준으로 파인튜닝한 CAT-Net이 필요함(T19, CAT-Net 담당과 논의).
