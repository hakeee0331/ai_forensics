# 노트북 실행과 결과 전달

- 팀원이 로컬 노트북을 VS Code의 Colab 커널에서 실행하고, 출력이 저장된 파일로 보고서를 작성하는 절차임.
- 평가·EDA는 완료된 001·002를 참고함.
- CAT-Net 단일 이미지 동작은 [003 보고서](catnet/EXP_kimjaehak_003_catnet_pretrained_check_singleImage.md)를 참고함.
- 새 실행은 새 개인 번호로 진행함.

로컬 실행용 코드를 작성할 때는 별도 [데이터 배치 안내](../data/README.md)를 따름. 아래 Drive 마운트·경로·커널 연결 절차는 Colab 실행에 해당함.

## 1. 작업과 파일 준비

1. [TODO](../TODO.md)에서 현재 상태와 남은 작업을 확인함. [결과 목록](results.md)에서 기준 노트북·보고서를 읽음.
2. 실행할 작업을 정함. 함수 사용법은 001, 전체 데이터 EDA는 002를 기준으로 삼음. 학습 실험은 T03·T06의 환경·공통 조건을 먼저 확정해야 함. EDA·함수 검증은 필요한 패키지와 설정을 기록하며 진행할 수 있음.
3. [파일명 규칙](../CONTRIBUTING.md#실험-이름과-개인-번호)에 따라 자기 작성자 ID와 사용하지 않은 번호를 정함. 모든 모델·EDA 폴더의 노트북과 보고서를 확인함. 다른 팀원의 번호를 이어받지 않음.
4. 기준 노트북을 같은 작업 종류의 폴더에 새 이름으로 복사함. 복사본의 작성자·날짜·목적·상태(`작성 중`)·보고서 링크를 수정하고, 기준 보고서 링크를 남김. 복사본의 이전 출력·실행번호·사람 검토 메모를 비우고 환경 메타데이터가 이전 실행 기록임을 확인함. `metadata.colab.name`이 있으면 새 파일명으로 맞춤.
5. 같은 이름의 보고서 초안을 대응하는 `docs/` 폴더에 만듦. 결과는 `미실행`으로 표시하고 기준 보고서의 점수를 새 결과로 옮기지 않음. TODO와 EDA/실험 목록에 작성 중 상태를 연결함.

완료된 노트북을 열어 읽는 것은 가능하지만 원본에서 셀을 실행하거나 출력을 지우지 않음. 새 실행 없이 기존 결과에 해석만 추가한다면 개별 보고서에 날짜와 검토자를 남김. 이미 확정한 002의 사람 검토 메모를 채우기 위해 원본 노트북을 수정하지 않음.

## 2. 공유 Drive 준비

공유받은 `AI_Forensics` 폴더의 바로가기를 자신의 Google Drive `내 드라이브` 최상위에 같은 이름으로 추가함. Colab에서 로그인할 계정으로 데이터 파일을 열 수 있는지 확인함. 바로가기만 추가한다고 원본 폴더의 읽기·쓰기 권한이 새로 생기는 것은 아님. 공통 코드 업로드 권한이 없으면 업로드 담당자에게 반영을 요청함.

현재 노트북이 사용하는 필수 경로는 다음과 같음.

```text
/content/drive/MyDrive/AI_Forensics/
├── datasets/
│   ├── AutoSplice/AutoSplice.zip
│   └── CocoGlide.zip
└── project/
    └── scripts/
        ├── __init__.py
        ├── datasets.py
        ├── preprocessing.py
        ├── evaluation.py
        ├── create_autosplice_split.py
        └── splits/
            ├── README.md
            └── autosplice_seed42.csv
```

로컬 프로젝트의 `scripts/` 전체를 `AI_Forensics/project/` 아래에 업로드함. 데이터 ZIP은 공유된 파일을 그대로 사용함. 분할 CSV를 다시 생성하지 않음. 노트북과 보고서는 로컬 프로젝트에서 관리하며, 현재 코드 실행을 위해 Drive에 업로드할 필요는 없음.

로컬 파일 저장·Git 커밋·push는 Drive 업로드를 대신하지 않음. 공통 코드 변경 시 [필수 업로드 절차](../README.md#공통-코드-수정-후-drive-업로드--필수)를 따름. 여러 팀원이 같은 Drive 코드를 사용하므로 실행 중에 다른 버전으로 교체하지 않도록 업로드 시점을 맞춤.

### 사전학습 가중치를 사용하는 경우

`scripts/`와 동일하게, 로컬 가중치를 추가·변경하면 다음 실행 전에 Drive에도 반영해야 함. 저장 위치는 `AI_Forensics/project/models/pretrained/<모델명>/`이며, CAT-Net은 `catnet/CAT_full_v2.pth.tar`를 사용함. 기존 예제·EDA에는 가중치가 필요하지 않음.

가중치는 Git에서 제외되므로 clone·pull만으로 준비되지 않음. Drive에서 `/content` 아래로 복사한 뒤 SHA-256을 대조하고, 실제 사용한 파일의 출처·크기·해시를 출력에 남김. 파일을 교체하면 런타임 복사본과 메모리의 모델도 다시 로드해야 함. 상세 경로와 업로드 절차는 [사전학습 가중치 안내](../models/pretrained/README.md)를 따름.

## 3. VS Code에서 Colab 연결

1. VS Code에서 로컬 프로젝트 폴더와 새로 만든 `.ipynb`를 엶.
2. Google의 [Colab 확장](https://marketplace.visualstudio.com/items?itemName=google.colab)을 설치함. 노트북 오른쪽 위 `Select Kernel`에서 `Colab`을 선택하고 로그인·런타임 연결을 진행함. 공식 빠른 시작은 `Auto Connect`를 안내함. 화면 구성은 확장 버전에 따라 달라질 수 있으므로 [공식 안내](https://github.com/googlecolab/colab-vscode#quick-start)를 참고함.
3. 선택한 커널이 로컬 Python이 아닌 Colab인지 확인함. 현재 EDA·평가 함수 예제는 GPU를 사용하지 않음.
4. 작성 중인 노트북의 최종 실행은 커널을 재시작하고 이전 출력을 지운 뒤 시작함. 파일명을 다시 확인해 완료된 원본을 실행하지 않도록 함.
5. 첫 준비 셀의 `drive.mount("/content/drive")`를 실행하고 Drive 접근을 승인함. 이미 마운트돼 있다면 경로에 필요한 파일이 있는지 확인함.

커널 재시작은 Python의 모듈·변수 상태를 초기화하는 절차임. `/content`의 ZIP·해제 파일을 모두 지우는 절차는 아님. 새 압축 해제를 검증하려는 작업은 기존 파일이 없는 새 런타임에서 시작하고, 실제 해제 출력으로 확인함.

## 4. 공통 코드 확인 후 위에서부터 실행

준비 셀에서 `project_root`는 `/content/drive/MyDrive/AI_Forensics/project`를 가리켜야 함. `scripts/` 폴더 자체가 아니라 그 상위 폴더를 `sys.path`에 추가한 뒤 `from scripts...`로 가져옴. `scripts/__init__.py`도 업로드돼 있어야 함.

002의 준비 셀은 필수 파일·모듈의 실제 import 위치·기대 SHA-256을 확인함. 새 노트북에도 이 방식으로 실제 사용하는 공통 파일을 확인함. 평가 함수를 추가로 사용한다면 `evaluation.py`도 검사·기록 대상에 포함함. 001은 코드 해시를 출력하지만 기대 코드 해시와 자동 대조하지 않으므로 이 차이에 주의함.

기대 해시와 다르면 로컬 코드·Drive 코드·기준 보고서의 버전을 먼저 대조함. 의도한 공통 코드 변경이라면 새 노트북에 변경 이유·새 버전을 기록하고 검증한 파일의 해시로 갱신함. 오류를 없애려고 해시 검사만 끄거나 현재 값으로 무조건 덮어쓰지 않음. 데이터 ZIP·분할 CSV가 다르면 원인을 확인하기 전 다음 셀로 진행하지 않음.

이후 셀은 위에서부터 순서대로 실행함.

| 단계 | 확인할 내용 |
| --- | --- |
| 환경·설정 | 실제 Python·패키지 버전, 코드·분할 해시, 최종 설정이 출력됨 |
| ZIP 준비 | `prepare_dataset_zip`이 ZIP을 확인하고 새 해제 또는 기존 해제 재사용을 출력함 |
| 데이터 연결 | AutoSplice 원본 ID train 1,818·val 227·test 228, JPEG 품질별 같은 split, CocoGlide 외부 테스트 연결을 확인함 |
| 분석·평가 | 해당 노트북의 표·그림·검증문을 확인함. 설명용 예측 점수를 모델 성능으로 해석하지 않음 |
| 사람 검토 | 마스크 정합성·의심 사례의 ID와 이유를 작성 중인 노트북의 검토 메모에 남김 |

AutoSplice는 `/content/datasets`에 해제해 그 안의 `AutoSplice/`를 읽고, CocoGlide는 `/content/datasets/CocoGlide`에 해제함. ZIP 내부 최상위 구조가 달라 해제 위치도 다름. 완료 표시를 이용한 재사용은 해제 파일의 내용을 매번 검증한다는 뜻이 아님. 직접 수정한 해제 파일로 검증을 이어가지 말고 원본 ZIP에서 새로 준비함.

## 5. 저장·검토·확정

1. 실행 종료 또는 실패·중단 상태를 첫 Markdown 셀에 표시함. 성공한 실행도 출력 검토를 마치기 전에는 확정하지 않음.
2. 출력과 사람 검토 메모를 포함해 로컬 `.ipynb`를 저장함. 파일을 닫았다 다시 열어 표·그림·오류·실행번호가 남아 있는지 확인함. 실패한 경우 오류와 진행된 셀을 보존함.
3. 검토자에게 저장한 노트북 경로, 실행 완료·실패·중단 여부, 바꾼 설정과 특이사항을 전달함. 화면 캡처만으로 실행 결과 전체를 대신하지 않음.
4. 검토자는 저장된 소스·실행번호·오류·표·그림·환경·해시를 읽고 같은 이름의 보고서를 갱신함. 저장되지 않았거나 출력에서 생략된 값은 추측하지 않음. 표를 모두 읽어야 한다면 다음 실행 전에 작성 중인 노트북의 출력 형식을 보완함.
5. [결과 목록](results.md)과 TODO를 갱신하고 노트북·보고서·목록의 숫자와 상대 링크를 대조함. EDA는 EDA 목록에 기록함. 실행·출력 검토를 마치면 최종 상태를 저장하고 노트북을 확정함.

노트북 완료와 TODO 전체 완료는 별개임. 002는 실행·출력 검토를 마쳤지만 사람의 시각 판단과 근접 중복 검토 범위·분할 최종 확정이 남아 T05는 검토 필요 상태임. 저장 출력에서 002는 기존 해제 파일을 재사용했으므로 새 해제를 검증했다고 기록하지 않음.

현재 001의 준비 설명에 있는 실행용 ZIP과 Drive의 notebooks·docs 복사는 필수 절차가 아님. 재사용 시 이 문서의 준비 구조를 따름. 002의 새 압축 해제 안내와 실제 재사용 결과의 차이는 [개별 보고서](eda/EXP_kimjaehak_002_dataset_eda.md)에 기록돼 있음. 완료된 원본은 그대로 보존함.

## 오류가 나면 확인할 곳

| 증상 | 확인·대응 |
| --- | --- |
| `google.colab`을 찾지 못함 | 먼저 커널이 Colab인지 확인함. 로컬에 패키지를 설치하는 것으로 대체하지 않음 |
| `AI_Forensics` 또는 ZIP을 찾지 못함 | 로그인 계정, 공유 접근 권한, MyDrive 바로가기 이름·위치와 실제 파일명을 확인함 |
| `scripts.preprocessing` 등을 찾지 못함 | Drive의 필수 파일과 `__init__.py`, 폴더 중첩, `project_root`를 확인함. 수정·업로드 후 커널을 재시작함 |
| 다른 `scripts` 경로를 import함 | 프로젝트 루트 경로와 import 위치를 확인하고 커널을 재시작함 |
| 코드·분할·ZIP 해시 불일치 | 업로드 버전과 기준 버전을 대조함. 데이터·분할을 임의로 바꾸지 않음 |
| NumPy·Pillow 등 패키지 import 실패 | 실제 런타임과 누락 패키지를 기록하고 설치 방법을 확인함. 확인하지 않은 버전을 팀 필수 버전으로 지정하지 않음 |
| 해제 완료 표시가 있는데 파일이 없거나 달라짐 | 출력부터 저장한 뒤 새 런타임에서 원본 ZIP으로 준비함. 완료 표시만으로 데이터 정상 여부를 판단하지 않음 |
| 저장 파일에 출력이 없음 | 열린 파일의 위치와 저장 여부를 확인함. 남아 있지 않은 결과는 미측정으로 두고, 재실행이 필요하면 보존 규칙을 따름 |

## 에이전트에게 맡기는 범위

에이전트는 [AGENTS.md](../AGENTS.md)에 따라 문서·노트북 작성, 공통 코드 검토, 저장 출력 검토와 보고서 갱신을 수행함. 현재 팀 절차에서 Colab 로그인·Drive 권한 승인·업로드·셀 실행·출력 저장은 팀원이 수행함. 문서가 있어도 이 단계가 자동으로 실행되는 것은 아님.

실행을 넘길 때는 새 노트북과 보고서 경로, Drive에 반영할 파일, 실행 순서, 확인할 출력과 미정 항목을 전달함. 저장된 결과가 없으면 미실행으로 남기고 실제 실행·업로드를 완료한 것으로 기록하지 않음.
